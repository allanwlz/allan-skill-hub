# 2026-10-05 香港中转东京：脱敏案例

原目标：通过中转域名的 TCP/UDP 20000–30000 访问目标服务器同号端口；代码、下载与运行文件区分 dev/test/prd。

环境：香港 Ubuntu 18.04/4.15 内核，使用官方用户态 WireGuard；东京 Ubuntu 24.04/6.8 内核，使用内核 WireGuard。示例版本仅说明当时环境，不推荐新部署继续使用旧系统。没有升级内核或重启服务器。

原方案 WireGuard + DNAT/SNAT 可达，但下载速度没有改善。先确认隧道约 164 Mbps，而完整连接持续重传/乱序，东京 CUBIC 窗口降至 2–4 个报文，RTT 约 95–98 ms。香港默认 BBR 对转发中的连接不生效。

| 当时模式 | 实际样本 | 耗时 | 平均速度 |
| --- | --- | --- | --- |
| 目标到中转，隧道 HTTP | 16 MiB 完整 | 0.82 s | 164 Mbps |
| 中转到客户端，SSH 禁压缩 | 16 MiB 完整 | 26.10 s，含 SSH 启动 | 5.14 Mbps |
| NAT 完整路径 | 14,614,640 B，超时 | 240 s | 0.49 Mbps |
| NAT 同端口短采样 | 1,742,336 B，超时 | 30 s | 0.46 Mbps |
| HAProxy 单端口对照 | 16 MiB 完整 | 26.37 s | 5.09 Mbps |
| HAProxy 全范围部署 | 16 MiB 完整 | 25.07 s | 5.35 Mbps |
| 防火墙/代理服务重启后 | 16 MiB 完整 | 25.32 s | 5.30 Mbps |

修复：HAProxy 3.4.6 在中转终止 TCP，目标连接独立经过隧道，省略后端端口保留同号映射。UDP 保持 NAT。范围共 10001 个监听 socket，最大并发 4096、fd 上限 65536、24 小时空闲超时。系统旧仓库只有过时的 HAProxy 1.8，因此从官方维护分支源码构建并核验 SHA256。

TCP/UDP 范围两端及中间点成功；后续 UDP 样本 9/10、9/10、10/10，说明并未消除网络波动。旧 NAT 样本超时且时长不同，“约 11 倍”是当时观测，不是未来速度承诺，也不是精确丢包位置或端口限速证据。

保留了原配置、专属链及回滚流程。临时后端和试验规则清理，原网站、VPN、Docker 和 FRP 保持存活；验证了服务重启与开机启用，未测整机重启。真实地址、域名、账号密钥和生产配置不在本仓库中。
